# Translation guide

[Project home](../README.en.md) · [简体中文](i18n.md) | English

The interface uses gettext, with English source strings in the code and Simplified Chinese translations in [`po/zh_CN.po`](../po/zh_CN.po). It follows the GNOME session language and falls back to English when no translation is available. `C` / `POSIX` environments use the English source text. Language selection does not affect network region detection.

Run all commands below from the project root. You need the gettext tools (`sudo apt install gettext` on Ubuntu).

## Edit a translation

Find the message in the `.po` file and edit only `msgstr`. Leave `msgid` unchanged so it still matches the code:

```po
msgid "Find my location"
msgstr "定位当前位置"
```

Keep placeholder names such as `{location}` intact; you can change their position. Missing translations, entries marked `fuzzy`, or mismatched placeholders will block the build.

After editing, run `python3 scripts/install.py`. The installer validates and compiles translations and backs up the old version. Save your work, log out and log back in to load the new text. To compile without installing, run `npm run i18n:compile`.

## Add a language

Create a translation file from the template. For example, for French:

```bash
npm run i18n:update
msginit --no-translator --locale=fr --input=po/classic-gadgets.pot --output-file=po/fr.po
```

Fill in the translations, translator details and the language's `Plural-Forms`. Use a gettext language identifier for the filename, such as `fr.po` or `pt_BR.po`. The `Language` header must match the filename without `.po`. Translate every plural form of every message.

When finished, run:

```bash
npm run i18n:check
npm run build
```

The build picks up all `.po` files under `po/`; no separate language list is needed. After installing, select that system language and log in again. The repository currently ships only a Simplified Chinese catalog; French is just an example.

## Edit source strings

Wrap complete sentences in `_()`, use named placeholders for variables, and use `ngettext()` for plurals:

```js
_('Find my location')
format(_('Selected {location}'), {location: cityName})
format(ngettext('{count} item', '{count} items', count), {count})
```

Import these functions from `extension/lib/i18n.js`, adjusting the relative path for the calling file. Use `pgettext()` to distinguish meanings of the same word, and `formatDate()` / `formatNumber()` rather than hard-coded language formats. Use getters for module-level display names so translation happens after initialization. Mark strings in static tables with `N_()` and translate them when displayed.

After changing English source text, update the template, fill in the translations for each language, then compile:

```bash
npm run i18n:update
# Edit new or changed translations in po/*.po
npm run i18n:compile
```

Do not edit the generated `po/classic-gadgets.pot` or `.mo` files under `extension/locale/` by hand. Keep configuration keys, widget IDs, paths, API parameters, stock symbols and place names used to match service responses unchanged. Do not send user content or service data through gettext. The product name in extension metadata remains “Windows Vista/7 小组件”, and text embedded in skin images does not change with the language.

## Check

```bash
npm test
npm run test:i18n
```

The first command includes translation and formatting unit tests. The second also checks Chinese and English windows and desktop menus in an isolated GNOME session without changing your current desktop configuration. Chinese tests require the system's `zh_CN.UTF-8` locale to be generated.
