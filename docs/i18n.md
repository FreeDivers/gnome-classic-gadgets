# 翻译说明

[项目首页](../README.md) · 简体中文 | [English](i18n.en.md)

界面使用 gettext，代码中的原文是英文，简体中文译文在 [`po/zh_CN.po`](../po/zh_CN.po)。语言跟随 GNOME 会话设置，没有对应翻译时回退到英文；`C` / `POSIX` 环境使用英文原文。语言选择不影响网络地区检测。

以下命令都在项目根目录运行，需要 gettext 工具（Ubuntu：`sudo apt install gettext`）。

## 修改译文

在 `.po` 文件中找到原句，只改 `msgstr`，不要改用于匹配代码的 `msgid`：

```po
msgid "Find my location"
msgstr "定位当前位置"
```

保留 `{location}` 这类占位符的名称，可以调整位置。缺译、标为 `fuzzy` 的条目或占位符不一致都会阻止构建。

修改后运行 `python3 scripts/install.py`。安装器会校验、编译翻译并备份旧版；保存工作后注销再登录，让新文案生效。只想编译、不安装时，运行 `npm run i18n:compile`。

## 添加语言

从模板创建译文文件，例如法语：

```bash
npm run i18n:update
msginit --no-translator --locale=fr --input=po/classic-gadgets.pot --output-file=po/fr.po
```

填写译文、翻译者信息，以及符合目标语言的 `Plural-Forms`。文件名使用 gettext 语言标识，如 `fr.po`、`pt_BR.po`；文件头的 `Language` 要与文件名一致。每条消息的所有复数形式都需要译全。

完成后运行：

```bash
npm run i18n:check
npm run build
```

构建会自动处理 `po/` 下的所有 `.po` 文件，不需要另加语言清单。安装后选择相应系统语言并重新登录。当前仓库只有简体中文译文，法语只是示例。

## 修改代码中的文案

用 `_()` 标记完整句子，变量使用命名占位符，数量使用 `ngettext()`：

```js
_('Find my location')
format(_('Selected {location}'), {location: cityName})
format(ngettext('{count} item', '{count} items', count), {count})
```

这些函数从 `extension/lib/i18n.js` 导入，实际相对路径按文件位置调整。需要区分同一词语的不同用途时用 `pgettext()`；日期和数字用 `formatDate()`、`formatNumber()`，不要写死语言格式。模块顶层的显示名称用 getter 延迟翻译，静态表里的文案用 `N_()` 标记、显示时再翻译。

修改英文原文后，先更新模板，再补齐各语言译文并编译：

```bash
npm run i18n:update
# 编辑 po/*.po 中新增或变动的译文
npm run i18n:compile
```

不要手动编辑生成的 `po/classic-gadgets.pot` 或 `extension/locale/` 下的 `.mo` 文件。配置键、组件 ID、路径、接口参数、证券代码及用于匹配服务响应的地名保持原样；用户内容和服务返回的数据不送入 gettext。扩展元数据里的产品名仍为“Windows Vista/7 小组件”，皮肤图片上的文字也不会随语言切换。

## 检查

```bash
npm test
npm run test:i18n
```

前者包含翻译和格式化的单元测试；后者还会在隔离的 GNOME 会话中检查中英文窗口和桌面菜单，不改当前桌面配置。中文测试需要系统已生成 `zh_CN.UTF-8` locale。
